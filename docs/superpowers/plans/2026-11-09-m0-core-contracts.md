# M0: core contracts and deterministic scheduler

**Goal:** первый небольшой Java-срез: типизированные события/эффекты, порты адаптеров и проверяемый порядок виртуальных событий.

**Architecture:** `quorum-core` зависит только от JDK; `quorum-simulator` зависит от core. Ядро получает событие и возвращает эффекты, I/O выполняют будущие адаптеры. Scheduler — одна очередь, один поток, время `(nanos, insertionOrder)`.

**Tech stack:** существующие Java 21, Gradle Wrapper и JUnit 5; новые библиотеки не нужны.

**Основание:** прямой запрос пользователя от 2026-11-09; [ТЗ §4](../../TECHNICAL_SPECIFICATION.md), QL-003/QL-004. Направление event → effects уже выбрано. Детали ниже — решения реализации этого среза, не новые требования исходного ТЗ.

## Границы

- Одна ветка `feat/m0-core-contracts`, текущий checkout, один исполнитель. Push делает пользователь.
- Начальные контракты: term/vote/commit metadata, RequestVote, таймеры, persist completion/failure, Storage/Transport/clock/RNG. AppendEntries, клиентские команды, apply и snapshots расширят контракты в своих этапах.
- Без реализации выборов, WAL, сети, fault injection или полного runtime. Не объявлять persist safety доказанной только наличием DTO.
- ID операции содержит incarnation узла и sequence; completion сам по себе не разрешает ответ без проверки ожидаемой операции и актуального состояния.
- Scheduler только выдаёт следующий элемент и двигает часы. Он не исполняет пользовательский код, не ждёт реального времени и не имеет скрытого бесконечного event loop.

## Review focus

Идентичность операций после restart; невозможность случайного изменения DTO; стабильный tie-break очереди; отсутствие wall clock/I/O в production core; невыполненные gates явно отделены от проверенных результатов.

## Результат выполнения

Выполнено inline одним агентом. RED: core 32/36 падений на отсутствующих проверках, scheduler 8/8 на заглушках. GREEN: 44/44 без failures/errors/skips на Windows и WSL, полный `clean test build`. Core runtimeClasspath пуст, simulator использует только core. Проверены локальные Markdown-ссылки, diff whitespace и сохранность исходных ТЗ/контекста. Самопроверка порядка очереди и persist-контракта не выявила блокирующих замечаний. Контрактные правила stale completion, persist-before-response и fail-stop ещё требуют реализации и тестов M1/M2; эта граница явно сохранена в ADR и приёмке.
