Полное ТЗ используется как опорный документ: поясняющий текст прямо ссылается на него и содержит менее подробные формулировки. Это рабочий порядок чтения, а не разрешение молча разрешать существенные противоречия; неоднозначности перечислены в [обзоре](../PROJECT_BRIEF.md).

Дальнейшие изменения требований фиксируются явно с объяснением и ADR, когда он уместен. Оригинальный поясняющий файл остаётся историческим источником.
