Это заменяет прежнее правило ручного выполнения всех команд пользователем. Computer use в QuorumLab запрещён. Пользователь подтвердил Java 21/Git, расширения VS Code и создал [GitHub-репозиторий](https://github.com/yergaliuly/QuorumLab). ## Учебный формат

Работа идёт небольшими шагами: цель и понятия → реализация ассистентом → тесты и проверка → объяснение результата на примере → следующий шаг. Ассистент выполняет обычные локальные команды сам. Пользователь отправляет изменения на GitHub через push. Нельзя обходить эту границу прямой записью кода через GitHub API. Чтение файлов, подготовка кода, тестирование и ведение документации выполняются без computer use.

Для каждой новой технологии нужно объяснять её общее назначение и конкретную роль в QuorumLab. Код разбирается через данные, переходы состояния и эффекты. Объяснения даются по мере работы и после каждого этапа. Если возникла ошибка, объяснить симптом, причину, исправление и проверку; если ошибки не было, не выдумывать её.

**Пройденные темы:** обзор замысла и M0, назначение java/javac/Git, отличие Java-кода от Kotlin DSL настройки Gradle и роль VS Code; локальный репозиторий, main, origin и назначение PR. Текущая тема — `.gitignore`, коммит, переносы строк и отличие автора коммита от аккаунта HTTPS-аутентификации. Практическая сборка, Raft, storage и тестирование ещё не разбирались; наличие ТЗ не означает, что пользователь уже освоил эти темы.

## Текущий учебный шаг

Стартовый коммит содержит сохранённые исходники и проектную документацию, `.gitignore` и `.gitattributes`. В `.gitignore` исключены Gradle/build output, локальные IDE-настройки, будущие node_modules/dist, data/logs/tmp, heap dumps и `.env`; сохранена возможность отслеживать Gradle Wrapper, `.env.example`, общие рекомендации расширений VS Code и test fixtures. `.gitattributes` задаёт LF для поддерживаемой документации и запрещает конверсию двух исходных файлов, чтобы сохранить их байты.

Проверены 15 примеров исключаемых путей и 9 примеров сохраняемых путей. Первая проверочная команда дала ложное расхождение: PowerShell передавал строки в stdin с CRLF, Git воспринимал CR как часть пути. Диагностика `git check-ignore --verbose` выявила причину; повторная проверка передавала каждый путь аргументом и прошла. Правила `.gitignore` менять для этого не потребовалось. Это ошибка проверочной команды, не приложения.

Автор коммита и аутентификация проверены отдельно. Устаревшее глобальное имя автора не означало вход под тем аккаунтом: GCM перечислил только yergaliuly, его локальная учётная запись подтвердилась через API. Для QuorumLab настроены локальные `user.name`, noreply `user.email` и `credential.https://github.com.username`; глобальные настройки пользователь может заменить предложенными командами. Токены в файлы и вывод проверки не записывались. Push не выполнялся.

Следующее действие пользователя после локального коммита — `git push -u origin main`. После подтверждения отправки продолжаем M0: согласовать границы компонентов и Linux-проверки, затем реализовать фундамент. PR рекомендованы для логически законченных изменений; обязательное требование чужого approve не настраивалось. Kotlin DSL относится к настройке Gradle; Android Studio не требуется.
